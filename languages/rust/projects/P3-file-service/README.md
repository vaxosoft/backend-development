# P3: File Service

An upload/download service that **streams** files to and from disk (never holding a whole file in memory), hashes them on the way in, and treats every client-supplied name as hostile.

**Modules exercised:** [02 HTTP server](../../modules/02-http-server/README.md), [08 File and stream I/O](../../modules/08-file-and-stream-io/README.md).

## Requirements

| Endpoint | Behaviour |
|----------|-----------|
| `POST /files` | `multipart/form-data`, the file is in the field named `file` (other fields are ignored). `201` + `Location: /files/{id}` + `{"id","name","size","sha256","content_type"}` |
| `GET /files/{id}` | `200`, body streamed from disk, with `Content-Length`, `Content-Type` (as uploaded, default `application/octet-stream`), `Content-Disposition: attachment; filename="<name>"`, `ETag: "<sha256>"`. A matching `If-None-Match` (`"<sha256>"`, weak `W/"..."`, a comma-separated list, or `*`) -> `304`, no body, `ETag` still set |
| `DELETE /files/{id}` | `204`; unknown id -> `404` |

- Size limit: `Config::max_size` bytes (default 5 MiB, env `MAX_UPLOAD_BYTES`). A file of exactly the limit is accepted, one byte more -> `413` `payload_too_large`. The limit is enforced **while streaming** (the declared length can lie), and a rejected upload leaves nothing on disk.
- Missing `file` field, a body that is not multipart, or a malformed multipart body -> `400` `bad_request`.
- Ids are generated by the server: 32 lowercase hex characters. Anything else in the path (`../x`, `%2e%2e%2f..`) -> `404` and never touches the file system.
- Files are stored in `Config::storage_dir` (env `STORAGE_DIR`, default `./storage`, created if missing) as `<id>.bin` + `<id>.json` (metadata). The client's name is **never** used as a path.
- Display-name sanitising: keep only what follows the last `/` or `\`; drop control characters; `"` -> `_`; collapse `..`; at most 100 characters; empty (or `.`) -> `file`. `../../etc/passwd` is stored as the name `passwd`. In the `Content-Disposition` header non-ASCII characters become `_` (the JSON keeps the real name).
- Errors use the JSON envelope `{"error":{"code","message"}}` (`error.rs` does it for you).

## Acceptance criteria (test names in `starter/tests/file_service.rs`)

| Criterion | Tests |
|-----------|-------|
| Upload metadata, `Location`, hash, type | `upload_returns_201_with_id_name_size_hash_and_type`, `upload_without_a_content_type_defaults_to_octet_stream`, `upload_accepts_an_empty_file`, `upload_assigns_a_distinct_id_to_every_file` |
| Size limit -> 413, streaming, cleanup | `upload_over_the_limit_is_413_payload_too_large`, `upload_exactly_at_the_limit_is_accepted`, `default_limit_is_5_mib`, `rejected_upload_leaves_nothing_on_disk` |
| Bad uploads -> 400 | `upload_without_a_file_field_is_400`, `upload_that_is_not_multipart_is_400` |
| Name sanitising, no path escape | `traversal_filename_is_sanitized_and_cannot_escape_the_storage_dir`, `filenames_lose_separators_control_characters_and_dot_dot`, `very_long_filenames_are_truncated` |
| Download and headers | `download_returns_the_bytes_with_content_headers`, `download_header_filename_is_ascii_even_for_unicode_names` |
| Conditional GET | `matching_if_none_match_gives_304_with_no_body`, `if_none_match_understands_weak_validators_lists_and_star`, `non_matching_if_none_match_still_returns_the_file` |
| Unknown / hostile ids | `download_of_an_unknown_id_is_404`, `ids_that_look_like_paths_are_404_and_never_read_outside_the_storage_dir` |
| Delete | `delete_returns_204_and_removes_the_file_from_disk`, `delete_of_an_unknown_id_is_404` |

## How to run

Work in `projects/P3-file-service/starter/` (commands from `languages/rust/`):

```bash
cargo test -p p3-file-service          # starter: 22 tests fail until the TODOs are done
ADDR=127.0.0.1:8080 STORAGE_DIR=/tmp/files cargo run -p p3-file-service
```

```bash
curl -i -F 'file=@notes.txt;type=text/plain' localhost:8080/files
curl -i localhost:8080/files/<id>
curl -i -H 'If-None-Match: "<sha256>"' localhost:8080/files/<id>
curl -i -X DELETE localhost:8080/files/<id>
```

## Where the TODOs are

| File | Work |
|------|------|
| `src/rules.rs` | `sanitize_filename`, `is_valid_id`, `etag_matches`, `content_disposition` (pure functions) |
| `src/handlers.rs` | `upload`, `download`, `delete` (currently answer `501`) |

Provided: `error.rs` (envelope, `io::Error` and multipart error mapping), `store.rs` (paths, metadata files, `stream_file`), `lib.rs` (router, body-limit layer), `main.rs`.

<details>
<summary>Hints</summary>

- Start with `rules.rs`, then `delete`, then `download` (upload a file by hand with `curl -F` first), then `upload`.
- Take the extractor as `Result<Multipart, MultipartRejection>` so that "not multipart" becomes your envelope instead of axum's plain text.
- Loop `while let Some(mut field) = multipart.next_field().await?`, skip fields whose `name()` is not `"file"`.
- Per chunk (`field.chunk().await?`): add to the size, check the limit **before** writing, `Sha256::update`, `file.write_all(&chunk).await?`. Finish with `file.flush().await?` and `hex::encode(hasher.finalize())`.
- Write to `store.part_path(&id)` first, then `tokio::fs::rename` to `store.data_path(&id)` and `store.write_meta(..)`. On every error path remove the `.part` file.
- axum's default body limit (2 MiB) applies to `Multipart`; `lib.rs` already raises it for `POST /files`. Without that, uploads between 2 and 5 MiB would fail.
- `[(HeaderName, String); N]` is a valid response-header part: `([(header::ETAG, etag)], body).into_response()`.
- `header::CONTENT_LENGTH` must be the **file** size from the metadata; the body comes from `stream_file(file)`.
- Validate the id with `is_valid_id` in *every* handler that takes `{id}` before building any path.

</details>

## Stretch goals (not tested)

- `Range` requests (`206 Partial Content`) using `AsyncSeekExt`.
- RFC 6266 `filename*=UTF-8''...` so non-ASCII names survive the download.
- Gzip-compress on the way to disk (`flate2`) and decompress on download.
- A storage quota, or a background task that deletes files older than N days.
- Verify the stored file against its SHA-256 on download (detect corruption).
